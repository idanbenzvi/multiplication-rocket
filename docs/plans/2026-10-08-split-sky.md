# Split Sky: one constellation across two phones

Design and implementation plan for the first two-device mode.

## Goal

Two children, each with their own phone, put the phones **side by side**. One star array spans
both screens, split at the seam where the phones touch. Each child counts their own half, and
together they find the whole. This teaches the **distributive property**:
`6 × 8 = 6 × 3 + 6 × 5`. It's the same "break a hard fact into easy ones" idea as the strategy
hints, made physical and shared.

## Design

### Connecting

- **Host / Join with a 4-digit code.** One phone taps **Host** and shows a big code, e.g. `4821`.
  The other taps **Join** and types it on a number pad.
- The PeerJS cloud server does the introduction only. Game messages then go phone to phone over
  a WebRTC data channel (direct on the home Wi-Fi). Names and avatars never touch the server.
- The host picks which side its phone is on (left or right of the other), and can swap.
- If the connection drops (a phone sleeps, Wi-Fi blips), the guest gets **Reconnect**, which
  rejoins with the same code. The host keeps the game state and resends it, so nothing is lost.
- Known limit (accepted for now): no relay fallback, so networks with client isolation can't
  connect. The error screen says so in plain words.

### A round

The host picks a whole fact `rows × cols` (cols ≥ 3) through its pilot's mastery weighting and
splits the columns between the phones. When cols > 5, one half is a **5** (the classic split:
`7 × 8 = 7 × 5 + 7 × 3`). Otherwise the split is random. Which side gets the 5 is random too.

1. **Count your half.** Each phone shows only its own half of the stars, as "6 rows of 3", and
   asks how many. Each child answers privately on their own phone (4 choices). A right answer
   shows their chip `6 × 3 = 18`. Two misses reveal it.
2. **The whole sky.** Once both halves are in, both phones show both chips (`6 × 3 = 18` and
   `6 × 5 = 30`) and ask `6 × 8 = ?`. Each child answers on their own phone. A miss gives the hint
   `18 + 30`. Two misses reveal it.
3. **Lit.** When both are done, the constellation lights up: a glow wave that starts at the seam
   and runs outward across **both** screens (each phone delays its stars by their distance from
   the seam, so the wave looks continuous across the gap).

There are 5 rounds a game, then a summary: constellations lit, and how many were perfect (no
misses from either child). **Play again** or **Close**.

### Progress

- Each phone records **only its own pilot's** answers, in its own practice map and answer
  history (new source `sky`): the half fact, and the whole fact. Profiles live on each device,
  so this needs no syncing.
- Untimed. Phones and hands are being shuffled around, so speed means nothing here.

## Architecture

| Unit | Responsibility |
|---|---|
| `src/game/splitSky.ts` (pure) | Round building and column split, plus the game reducer (`lobby → count → join → lit → … → summary`), which the host runs as the referee. Unit-tested. |
| `src/net/peerLink.ts` | A thin wrapper over PeerJS (loaded lazily): host with a code (re-rolling a taken one), join, send/receive JSON, and status (`connecting / waiting / connected / lost / error`). |
| `src/game/useSkyStore.ts` | Session: role, code, my side, link status, synced state. The host applies actions through the reducer and broadcasts the full state after every change. The guest renders the state and sends its own answers as actions. |
| `src/components/sky/*` | `SplitSky` (full-screen overlay: lobby / play / summary), `SkyGrid` (the half array with seam alignment and the lit wave), `sky.css`. |
| Entry | A **📱📱 Split Sky** card in the pilot picker (needs just one pilot on each phone). It pauses the solo game while open. |

### Protocol (JSON over the data channel)

- guest → host: `{ t: 'hello', player }`, `{ t: 'act', action }` (only `answer` for the guest's own side is accepted)
- host → guest: `{ t: 'state', state, guestSide }` after every change and on (re)connect

## Implementation plan

1. Install `peerjs`, and add the `sky` answer source and pause reason.
2. **Write `splitSky.test.ts` first**, then implement `splitSky.ts`. Cover: the split (5 when
   cols > 5, both halves ≥ 1, sums to cols), round constraints, phase flow, misses → reveal,
   lit/perfect counting, ignoring answers in the wrong phase or for a finished side, and summary
   after the last round.
3. `peerLink.ts`.
4. `useSkyStore.ts`.
5. English and Hebrew strings.
6. UI: lobby (host code / join pad / side), play, summary, styles (phone first, RTL).
7. Wiring: the picker card and App overlay.
8. Verify with two real browser pages connected through the PeerJS cloud: host, join, play
   rounds on both, drop the connection and reconnect, then the summary.
9. README.

# Eclipse Hunters: the second two-phone game

Added to the same lobby: once both phones are in, the host picks **✨ Split Sky** or
**🌑 Eclipse Hunters**.

## Design

- Each phone has **one moon** orbiting a planet. Noa's moon goes round every **3** ticks, Ari's
  every **4**. The periods are a coprime pair from 2–10 with a product ≤ 60, picked through the
  host pilot's mastery weighting, so the first eclipse is exactly the product: `3 × 4 = 12`.
- **Orbit:** each child skip-counts their own moon, choosing the next tick each time (3, 6, 9,
  12, 15…). The moon flies one orbit per right answer. Every step is a times-table fact
  (`3 × 5 = 15`) and is recorded as one. A list runs 1–2 orbits past the eclipse (chosen at
  random), so the answer isn't simply the last number. Two misses on a step reveal it.
  - The partner's progress shows only as a count ("Ari: 3 / 5"), never the numbers.
- **Predict:** "When do both moons line up first?" Each phone shows only its own list, so the
  children have to compare out loud to find the first number in both. Both must answer: a miss
  hints "Find a number in both lists", and two misses reveal the answer.
- **Eclipse:** both moons swing into line, and a shadow sweeps across the left phone and then
  the right, followed by a corona glow. The explanation reads `3 × 4 = 12`: both moons line up
  again every 12 ticks.
- 4 rounds a game. The summary shows eclipses seen and perfect rounds.

## Architecture

- `src/game/eclipse.ts` (pure, tested): rounds, orbit/predict reducer, choices.
- `src/game/duo.ts`: the synced state is either game's (`game: 'split' | 'eclipse'`), plus
  `duoReducer`, which routes actions and switches game in the lobby while keeping the players.
- The session store, the link and the lobby are shared. A new play view for Eclipse goes in
  `components/sky/EclipsePlay.tsx`. Answers are logged with source `eclipse`.
